Privacy Policy

Effective 2026-08-30

gcal-sync is open-source software that you download and run yourself, on infrastructure you control. The project maintainer does not operate a hosted version of this service and never receives, stores, or has access to your Google account data. This policy describes how the software itself handles data when you run your own instance of it.

If you're using someone else's deployment of this software rather than running your own, that deployment is a separate operator's instance — see its own privacy policy (typically at its /privacy path) for how that specific operator handles your data.

Google data this software accesses

gcal-sync requests two narrow Google Calendar API scopes and nothing else:

  • calendar.events — to read events on the calendars you configure, and to create, update, or delete the private “Busy” placeholder events it uses to mirror availability across them.
  • calendar.calendarlist.readonly — to list the calendars visible to an authorized account, so you can pick which calendar ID to sync (used only by the calendars command).

gcal-sync never requests access to Gmail, Drive, Contacts, or any other Google product.

What gets copied between calendars

Only the start/end time, busy/free status, and recurrence pattern of a source event are copied into a placeholder mirror event on the other calendars. Titles, descriptions, attendees, locations, and conferencing links are never copied, read into logs, or stored anywhere. Events marked “Free” are ignored entirely.

Where data is stored

Everything gcal-sync needs to operate — OAuth tokens and a record of which source events map to which mirror events — is stored locally on the machine you deploy it on (as local files and a local SQLite database). None of it is transmitted to the project maintainer, to analytics providers, or to any other third party.

Data sharing

gcal-sync makes outbound HTTPS requests only to Google's Calendar API. It does not include analytics, tracking, advertising, or any other third-party integration.

Data retention and deletion

Data is retained only for as long as you, the operator, keep it. Deleting the local data/ directory removes all stored tokens and sync state. You can revoke gcal-sync's access to your Google account at any time from Google Account → Security → Third-party access.

Contact

Questions about this software can be raised via GitHub Issues on the source repository.
