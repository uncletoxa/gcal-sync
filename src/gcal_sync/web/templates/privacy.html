Google data this software accesses

gcal-sync requests two narrow Google Calendar API scopes and nothing else:

  • calendar.events — to read events on the calendars you configure, and to create, update, or delete the private “Busy” placeholder events it uses to mirror availability across them.
  • calendar.calendarlist.readonly — to list the calendars visible to an authorized account, so you can pick which calendar ID to sync (used only by the calendars command).

gcal-sync never requests access to Gmail, Drive, Contacts, or any other Google product.

What gets copied between calendars

The Calendar API returns full event data (including title, description, attendees, location, and conferencing links) when gcal-sync reads your calendar. By default, only the start/end time, busy/free status, and recurrence pattern are copied into a placeholder mirror event on the other calendars. Events marked “Free” are ignored entirely.

You can explicitly opt a specific direction between two of your own calendars into “full copy” mode, which additionally mirrors the event's title, description, location, and meeting link. This is off by default for every calendar and must be turned on deliberately per direction from your dashboard (or, for a self-hosted instance, via configuration). Attendees are never copied, under either mode.

For any calendar direction where full copy is not enabled, titles, descriptions, attendees, locations, and conferencing links exist only in memory for the moment it takes to process each event during a sync pass, and are discarded immediately afterward — they are never written to disk, to the database, to logs, or anywhere else.

Where data is stored

None of it is transmitted to the project maintainer, to analytics providers, or to any other third party.

{% endif %}

How this data is protected

All requests to Google's Calendar API are made over HTTPS/TLS; gcal-sync never transmits OAuth tokens or calendar data over an unencrypted connection.

{% if operator_name %}

On this instance, OAuth tokens are encrypted at rest in the database using symmetric authenticated encryption (Fernet, AES-128-CBC with an HMAC integrity check) before being written to storage, and are decrypted only in memory, only when needed to make a Calendar API call on your behalf. The encryption key is held separately from the database and is not accessible to anyone without direct access to {{ operator_name }}'s server environment. Access to the underlying database and server is restricted to {{ operator_name }}; no other party, and no other connected account, can read your tokens or synced event data.

{% else %}

On a self-hosted instance, OAuth tokens are written to local files with permissions restricted to the operating system user running gcal-sync (mode 0600: readable and writable only by that user). No other process or account on the machine can read them without elevated privileges, and nothing is transmitted off the machine except the HTTPS calls to Google's Calendar API described above.

{% endif %}

Data sharing

gcal-sync makes outbound HTTPS requests only to Google's Calendar API. It does not include analytics, tracking, advertising, or any other third-party integration.

To have your account record and all connected calendars removed entirely, contact us as described below.
